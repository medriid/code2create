# FILAMENT OS — submission site

The project site. One long vertical scroll: a pinned hero that performs the
demand-response demo while you scroll it, then every section of the plan opening
as it comes into view.

```bash
npm start          # build, then serve on http://localhost:5173
npm run dev        # serve and rebuild when src/ or content.mjs changes
npm run build      # write dist/index.html and stop
```

**There are no dependencies.** No `npm install`, no bundler, no network. `dist/`
is a single self-contained HTML file — you can open it straight off a USB stick
with no server at all, which is the same reason the product itself runs on a LAN.

## Deploying

Set Vercel's **Root Directory** to `web/submission` (its importer suggests this
anyway). The repo-root `vercel.json` supplies the rest: framework `Other`,
install `echo "no dependencies"`, build `npm run build`, output `dist`.

Paths in `vercel.json` resolve relative to the Root Directory, not the
repository root. Any static host works the same way — build, then serve `dist/`.

## How it's put together

| File | Job |
|---|---|
| `content.mjs` | Every word on the page, as data. The only file to edit for copy changes |
| `build.mjs` | Renders `dist/index.html`. Inlines the CSS, the JS and the brand SVGs |
| `server.mjs` | ~50-line static server. Refuses any path that escapes `dist/` |
| `src/styles.css` | Tokens, layout, and the two animation systems |
| `src/scroll.js` | The hero scrubber and the reveal observer |

The logo comes from `../../assets/brand/`, generated by that directory's own
`build.mjs`. Regenerate the brand first if you change the mark.

## The two animation systems

**The pinned hero.** `.journey` is 620 vh tall and contains one
`position: sticky` stage. A scroll listener converts scroll position into a
progress value, then interpolates the site cap and each home's draw between
consecutive scenes — writing CSS custom properties, never touching layout. Each
scene holds for the first 55% of its segment and transitions over the remaining
45%, which is what produces the settle-then-move rhythm rather than a constant
slide.

Because the numbers are interpolated rather than hard-coded per frame, the hero
is not an animation of the demo. It *is* the demo: total load, the cap, the
overload, the plan, and the stale gateway's conservative reserve are all real
values from `scenes` in `content.mjs`. Change a number there and the hero changes.

**Reveal on enter.** Everything below uses an `IntersectionObserver` that adds
`.in` once. `.reveal` fades and rises out of a blur; `.open-y` opens with a
`clip-path`; `.open-x` grows a rule from the left. Stagger comes from a `--i`
custom property on each child.

Both systems only ever animate `opacity`, `transform`, `filter` and `clip-path`,
so nothing hits layout.

## Accessibility and failure

- `prefers-reduced-motion: reduce` unpins the hero, stacks the six scenes as
  ordinary content, and disables every transition. The full narrative is still
  readable — nothing is motion-only.
- Fonts load from Google with real fallback stacks. Offline, the page falls back
  to a system serif, sans and mono and still looks deliberate.
- `scroll-behavior: smooth` is deliberately **not** set. The hero maps scroll
  position to state 1:1, and animated scrolling fights the scrub.
- No JavaScript at all still gives you every word — only the hero stops moving.
